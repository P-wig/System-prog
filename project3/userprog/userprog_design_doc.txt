---- DATA STRUCTURES ----

>> A1: Copy here the declaration of each new or changed `struct' or
>> `struct' member, global or static variable, `typedef', or
>> enumeration.  Identify the purpose of each in 25 words or less.

* struct process_status: Keeps track of child processes status manages communication between child and parent.
  * struct semaphore load_done: signals when load complete so parent can continue
  * struct semaphore dead: signals when child exits so parent can continue
  * bool load_result: after load_done signals, this informs parent what happened

struct start_process_args: bundles start process's args

---- ALGORITHMS ----

>> A2: Briefly describe how you implemented argument parsing.  How do
>> you arrange for the elements of argv[] to be in the right order?
>> How do you avoid overflowing the stack page?

* tokenizing the command line arguments and incrementing argc not to exceed MAX_ARGS. The parsing method keeps the arg order, and then we use reverse order for stack placement. If the command line is larger than the PGSIZE we alert the user, clean up, and return false

---- RATIONALE ----

>> A3: Why does Pintos implement strtok_r() but not strtok()?
* strtok relies on a shared static pointer, strtok_r has its own pointer to keep track of where it is.
